# Learning Roadmap

Three paths depending on your time and goals. Pick one. Finishing one path well is better than sampling three paths shallowly.

---

## Path 1: Two-week minimum

**For:** people preparing for interviews or wanting a quick but solid foundation.

| Week | Focus | Learn | Practise | Output to produce |
|------|-------|-------|----------|-------------------|
| 1 | Product thinking + SQL | Metrics, funnels, retention, SQL joins, window functions | Write 3 funnel queries, 1 retention query | Annotated SQL file with comments |
| 2 | Experimentation + communication | A/B testing basics, experiment readout template | One mock A/B test analysis | Written experiment readout (1 page) |

**How to know you understand it:**
- You can explain activation, retention and churn without looking at notes
- You can write a cohort retention query from scratch
- You can explain why peeking at p-values is a problem
- You can write a one-page experiment readout that a non-technical person can follow

---

## Path 2: One-month practical path

**For:** people transitioning into analytics DS or preparing for a more senior role.

| Week | Focus |
|------|-------|
| 1 | Product thinking: metrics, funnels, cohorts, metric diagnosis |
| 2 | SQL: all patterns, run all four SQL templates |
| 3 | Statistics and A/B testing: hypothesis testing, power analysis, common mistakes |
| 4 | Communication: insight writing, experiment readout, one case study |

**Outputs to produce:**
- A metrics framework for one fictional product (north star, input metrics, guardrails)
- Four SQL queries written from scratch: funnel, retention, cohort, experiment
- A written A/B test analysis with recommendation
- A one-page decision memo

**How to know you understand it:**
- You can diagnose a metric drop end to end, starting from "is the data real?" and ending with "here is my recommendation"
- You can design a basic A/B test: define the metric, calculate sample size, set the stopping rule
- You can write a recommendation a stakeholder can act on without asking follow-up questions

---

## Path 3: Three-month strong foundation

**For:** people wanting a thorough grounding in analytics data science, or preparing for senior roles.

| Month | Focus |
|-------|-------|
| 1 | Foundations: product thinking, SQL, statistics, experimentation |
| 2 | Advanced methods: causal inference, Python workflows, ML for analytics |
| 3 | Applied practice: dashboards, communication, case studies, interview prep |

**Outputs to produce:**
- Complete all exercises in sections 01–06
- Write one case study end to end (choose one from section 09)
- Build one dashboard spec document
- Complete a difference-in-differences analysis on a synthetic dataset
- Write five interview answers with worked examples, reviewed by a peer

**How to know you understand it:**
- You can handle any case study in section 09 without reading the solution first
- You can explain when to use DiD vs RDD vs matching and what would invalidate each
- You can write a complete experiment design document before a test launches
- You can present a finding to a non-technical stakeholder and answer their follow-up questions clearly

## A note on depth vs breadth

It is better to understand five topics deeply than ten topics shallowly. For each topic, the goal is not just to recognise the concept but to apply it to a problem you have not seen before. That is the standard for interviews and for real work.

When you complete a section, test yourself: can you explain the core idea in two minutes without notes? Can you apply it to a new example? If not, go back before moving forward.
